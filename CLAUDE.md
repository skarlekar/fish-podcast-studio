# Podcast Studio (repo: fish-podcast-studio)

One-page web app with two tabs. **Audio Summary**: Claude (Sonnet, `claude-sonnet-5-5`) writes a National Geographic-style, single-narrator story with Fish Audio tags; the user reviews/approves; Fish Audio voices it while Claude draws a cover illustration; podcast-style player, library, transcript, downloads: MP3 with embedded cover and lyrics, plus an iPhone-friendly `.m4a` (needs ffmpeg). **Podcast**: Claude turns a story into a two-host (male + female) conversation, voiced with both voices. Zero npm dependencies, Node 18+. Local folder is still named `FishAudioTrial`; the GitHub repo is `fish-podcast-studio`.

## How we work (the user's preferences, learned over sessions 1–2)
- The user gives direct requests and expects them built, **verified live**, and then reported plainly: what changed, how it was checked, anything they must do (usually: restart).
- **Test-first.** Add failing checks to `test/smoke.js`, implement, run `npm test`, then verify against the real APIs.
- **Live checks.** Start a temporary server on a spare port (`PORT=3301 node server.js` in the background), drive it with Playwright (screenshots land in `.playwright-mcp/`, git-ignored, delete it afterwards), then stop it.
- **Never kill processes by name or pattern** (a `pkill -f` once stopped the user's server, and killing a port's listener once killed Docker Desktop's `com.docker.backend`). Stop only exact PIDs verified as `node server.js`, or use `docker stop <container>`.
- Back up `output/` (to the scratchpad) before anything that rewrites the user's MP3s or episode files.
- **Commit and push only when the user asks.** Before every commit: `npm test`, scan the staged diff for keys, confirm no `.env`, `output/` or `.playwright-mcp/` is tracked. Commit messages end with the Co-Authored-By line. The repo is PUBLIC.
- After `server.js` changes the user must restart: `./start.sh` (answer **y** to the busy-port prompt) or `./start-docker.sh`. Changes to `public/` only need a page reload.
- The user usually runs the Docker container `podcast-studio` on port 3000; it bind-mounts this folder's `output/` and `.env`.
- Keep README.md (with screenshots in `docs/`) and this file current with every feature.

## Layout
- `podcast.js` — podcast mode: prompts (`DEFAULT_PODCAST_PROMPT`, `PODCAST_RULES`), `parseTurns`/`checkDialogue`, Fish dialogue windows (`chunkDialogue`, 700 chars), credits
- `server.js` — Node server: static files, Claude + Fish Audio proxy, key handling, range-served audio, episode library, illustrations, transcripts, ID3 cover + lyrics tagging, iPhone `.m4a` conversion via ffmpeg, sample seeding
- `public/` — `index.html`, `styles.css`, `app.js` (the one-page app), `default-art.svg` (series cover), `favicon.svg`
- `test/smoke.js` — `npm test`; runs the real server against mock Claude/Fish upstreams (75 checks, all passing; the `.m4a`/lyrics checks need ffmpeg and skip themselves without it; a run takes ~3 s)
- `start.sh` (npm start + open browser), `start-docker.sh` + `Dockerfile` (build, run container, open browser), `start-common.sh` (shared: busy-port prompt to stop + restart; stops a Docker-held port via `docker stop`, never by killing Docker's backend process; `FORCE=1`, `OPEN_BROWSER=0`, `PORT`)
- `samples/` — two finished episodes (mp3/json/txt/svg) copied into an empty `output/` on first start by `seedSamples()` (marker `output/.samples-added`; `SAMPLES_DIR` env for tests); included in the Docker image; `samples/README.md` notes Fish Audio's terms apply to the recordings
- `docs/` — README screenshots (`brief.png`, `player.png`, `podcast-brief.png`, `podcast-player.png`); `docs/superpowers/` — the podcast spec and plan; `LICENSE` — MIT
- `output/` — per episode: `.mp3`, `.json`, `.txt`, `.svg`, and a cached `.m4a` once downloaded for iPhone (git-ignored)

## Decisions already made (don't relitigate)
- Default audio engine `s2.1-pro-free`; selectable: s2.1-pro, s2-pro, drama-3, s1. Claude is Sonnet only (no picker; override via `CLAUDE_MODEL`).
- S2-family tags use [brackets]; `s1` uses (parentheses) with a fixed set, so the server converts and drops unknown tags.
- Keys: from `.env` / env vars, else the browser prompts on launch (held in server memory only; optional "save to .env" at mode 600). Never returned to the browser, never committed (`.env` and `output/` are git-ignored; `.env.example` has blank values).
- Server binds 127.0.0.1, rejects non-localhost Host headers and cross-origin POSTs, redacts keys from errors.
- Fish TTS: `POST https://api.fish.audio/v1/tts`, `Authorization: Bearer`, `model` header = engine. Voice search: `GET /model`. Fish MP3s arrive untagged.
- Prompts: the system prompt (style, `DEFAULT_SYSTEM_PROMPT`) and user prompt (brief) are both editable in the UI (system prompt remembered in localStorage). The server always appends `PROMPT_RULES` (length, tag syntax, output format, complete final sentence, no speaker labels) after the style, so edits can't break parsing.
- Claude call uses `max_tokens: 16000`: Sonnet 5.5 thinks by default and thinking counts against it (a 3000 cap truncated scripts mid-sentence). `stop_reason` `max_tokens`/`refusal` is an error, never a script. Scripts end with a goodbye.
- Fish API credit is billed separately from a fish.audio web subscription; a 402 means no API credit. Audio errors show next to the Approve button.
- Voices: default narrator `DEFAULT_VOICE_ID` = 933563129e564b19a115bedd57b7406a ("Sarah" by Fish Official; was Rogen Darell Aban's "Narrator" 785ee418…), override `FISH_VOICE_ID`. Fish `GET /model` searches titles only; `/api/voices` also takes a voice ID/fish.audio link in `q` (→ `GET /model/{id}`) and `author=<creator id>` (→ `author_id`). Official voices = author `FISH_OFFICIAL_ID` d8b0991f96b44e489422ca2ddf0bd31d ("Fish Official"); `/api/voices` with no query lists them (English, 24/page), title searches merge official matches first; items carry `official: true` and the UI shows an Official badge. Footnotes: `narratorCredit` → "Narrated by <voice name, or creator when the title is generic like 'Narrator'> (…, ID …)".
- Illustrations: one static cover per episode. `drawArt` asks Claude (ART_PROMPT, with `public/default-art.svg` as style reference) for an SVG while Fish voices the script; failure never blocks audio. `sanitizeSvg` strips scripts/handlers/foreign content/external refs; `/art/*.svg` served with a no-script CSP; shown only via `<img>`. `POST /api/illustrate {file}` draws one for an existing episode. Episodes without art show the default (mountains + auto road).
- Audio transcripts: `handleAudio` saves the exact text sent to Fish (after `prepareText`; chunks joined by blank lines) as `<episode>.txt`, `meta.transcript`; served at `/transcript/*.txt` (text/plain, no-script CSP, `?download=1`). Older episodes without one show no Transcript button. `prepareText` is unchanged since the first commit, so an old transcript can be rebuilt exactly from `meta.script` (done for the sample).
- MP3 cover tag: players need PNG/JPEG, so the browser renders the SVG (or `default-art.svg`) to a 600×600 PNG with the label (`renderCoverPng`, via a data: URL because the page CSP blocks blob: images) and `POST /api/cover {file, png}` writes an ID3v2.3 tag (TIT2, TPE1 = narrator, TALB = Podcast Studio, APIC, USLT lyrics) in front of the audio, replacing an earlier tag, via temp file + rename. `meta.coverOf` records which picture is embedded; `needsCover` in the episode list drives automatic backfill on library load; illustrate resets it.
- Voicing footnote: episodes record `meta.settings` = `voiceSettings()` {temperature, topP, speed, latency, mp3Bitrate, normalize, requests, voicing} built from the same `FISH_OUTPUT`/sampling constants `fishTts` sends; episodes without it get the narration values (0.7/0.7, normal, 128 kbps — unchanged from the first commit until the podcast-energy change). `settingsLine()` in app.js renders it under the player (`#playerSettings`) and in library rows (`.esettings`). Fish TTS has no top-k parameter.
- Delete: `POST /api/delete {file}` removes the .mp3 + .json + .svg + .txt + .m4a (bare `*.mp3` names only); the UI uses a two-click confirm, no modal.
- Docker: container listens on 0.0.0.0, published on host 127.0.0.1 only; runs as the host uid with `--init`; `.env` and `output/` are bind-mounted (never in the image); the image installs ffmpeg (`apk add ffmpeg`).
- iPhone sharing: Messages cannot play `.mp3` attachments (same file plays via AirDrop/WhatsApp; verified on iPhone 13 Pro Max + iPhone 18 Pro Max, incl. a tag-free file), but plays AAC. `GET /audio/<episode>.m4a` converts on demand with ffmpeg (needs ffmpeg; 501 with install hint otherwise), caches `<episode>.m4a` beside the MP3, and is removed on delete. Downloads (`?download=1`) always ignore Range so iOS never saves a partial file. The .m4a carries the title/artist tags and cover art (verified: plays in Messages on iPhone and in Apple Music/QuickTime on Mac). ffmpeg is installed in the Docker image (`apk add ffmpeg`); a brew-installed ffmpeg only helps `./start.sh`, not the container. Ruled out: MP3 stream inside an MP4 container (Apple players won't open it); `afconvert` was never needed. The .m4a cache has no version invalidation: delete `output/*.m4a` after changing the ffmpeg arguments. Lyrics: the MP3 carries the narration without `[audio tags]` in an ID3 `USLT` frame (`lyricsOf`/`episodeLyrics`), set whenever the cover is embedded; `meta.lyricsIn` marks episodes tagged that way and older ones report `needsCover` so the browser re-tags them on next load. ffmpeg reads USLT as `lyrics-eng`, which the MP4 writer drops, so `ensureM4a` passes `-metadata lyrics=` explicitly (becomes `©lyr`). The two repo samples were re-tagged with lyrics. Verified by the user: Apple Music's Lyrics button shows them. `<a download>` saves any response, so the client fetches first and never saves an error body as a file.
- Podcast tab (spec: `docs/superpowers/specs/2026-10-25-podcast-tab-design.md`, plan: `docs/superpowers/plans/2026-10-25-podcast-tab.md`, reviewed by an Opus examiner before building):
  - Script: `TITLE:` then one paragraph per turn `Name: …`. Only the two host names start turns (plus a denylist: Narrator, Both, Host, Guest, Speaker N…); a colon inside a sentence is not a label; preamble dropped; same-host turns merged. `checkDialogue` also rejects `(laughs)`/`*chuckles*`, a host with no lines, < 6 turns. One corrective Claude pass, then 502; never voiced. Length at 150 wpm; the length pass builds on the latest valid script.
  - Energy (user found the first episode dull): default hosts Mason (02e950ce…) + Harper (c250136a…), Fish Official young/conversational/confident/brisk; prompt asks for a high-energy show, a delivery tag on most turns, spoken laughter ([laughing] Ha!) ~6–8 times; podcast sampling 0.9/0.9 (drama-3 1.0/0.9, s1 0.7) vs summaries 0.7/0.7. Measured on the same story: pitch variation 3.24 → 3.86 semitones, pace 153 → 174 wpm; 21/21 turns on the right host.
  - Prompt: editable `DEFAULT_PODCAST_PROMPT` (placeholders `{{male}}`/`{{female}}`; hosts trade the skeptic role; first-person stories → "our storyteller"; opening that previews the topic, 2–3 takeaways, an unanswered listener question, goodbye) + fixed `PODCAST_RULES` appended by the server.
  - Voicing: Fish takes `reference_id: [maleId, femaleId]` + `<|speaker:0|>`/`<|speaker:1|>` per turn (S2 engines: two voices per request in ≤700-char windows. Drama 3 and S1: one request per turn with that host's voice — S1 has no multi-speaker mode; Drama 3's two-voice mapping couldn't be verified because its excited male lines jump into the female pitch range). One request for a whole episode gave 8 of 27 short reactions to the wrong host; windows of whole turns ≤ 700 chars got 28/28 right and were faster, so podcasts are ALWAYS voiced in ≤ 700-char windows, 3 concurrent, retry on 429/503 (`FISH_RETRY_MS`), joined in order. Live 24-turn test: 21/22 located turns right; one 2-second line slipped for ~0.6 s; retakes clean. Accepted residual risk; per-turn requests are the fallback if the user hears slips.
  - Meta: `mode: "podcast"`, `speakers: [{name, voiceId, voiceTitle, voiceAuthor}]` (0 = male, 1 = female), `source` (the story). Transcript `.txt` keeps the speaker markers; lyrics and the transcript dialog name the hosts; ID3/`.m4a` artist "Mason & Harper"; footnote "Hosted by …" (a renamed host credits the voice). Illustration prompt is told it's a conversation and to draw the story, not the hosts.
  - UI: tabs (`switchMode`, `body[data-mode]` + `[data-mode-only]`), per-tab drafts (`swapDraft`) incl. engine, separate prompt boxes/keys (`podcastStudio.systemPrompt`, `podcastStudio.podcastPrompt`), tabs locked while a request runs, library filtered per tab (cover backfill still gets every episode), tab counts. Host cards + `voiceTarget`; renaming a host rewrites script labels (`renameLabels`); "Start from an episode" preselects the newest summary. Request bodies come from pure `buildNarrativeBody`/`buildAudioBody` (summary bodies unchanged, tested).
- Tests: every test server uses `PORT=0` (real port read from the "running at" line), extra servers are killed in `finally`, and the run ends with `process.exit` — fixed fixed-offset port clashes that could hang `npm test`.
- Git: this repo has `http.postBuffer=157286400` in `.git/config` (pushes with the sample MP3s failed with HTTP 400 at the default).

### Gotchas learned
- A cloud chat has no GitHub credentials, so it cannot `git push` or create repos; use this terminal session or the user's own terminal for that.
- A cached `output/<ep>.m4a` is reused while it is newer than its MP3. After changing the ffmpeg arguments, delete `output/*.m4a`.
- ffmpeg reads ID3 lyrics as `lyrics-eng`, which its MP4 writer drops; `ensureM4a` passes `-metadata lyrics=` instead.
- `<a download>` saves whatever the server returns, including an error body (this once produced a 159-byte fake `.m4a`); the client fetches first and only saves a real response.
- The user prefers verified claims: say what was tested and what only they can test (Messages, Apple Music).
